# 要件定義書: ワードソリティア

## 1. ユーザー要件

### 1.1 対象ユーザー
- 日本語を母語とするカジュアルゲームユーザー
- スマートフォン（Android優先、iOS次フェーズ）でプレイする想定
- Web ブラウザでもプレイ可能

### 1.2 ユーザーストーリー

#### ゲームプレイ体験
- **US-01**: プレイヤーとして、ステージを選択してゲームを開始したい（どのステージに挑戦するか選択できる）
- **US-02**: プレイヤーとして、山札から1枚めくってカードを入手したい（次の手を決める）
- **US-03**: プレイヤーとして、場のスタックの一番下のカードを取りたい（戦略的にカードを取得できる）
- **US-04**: プレイヤーとして、カテゴリカードをめくったらカテゴリスロットに配置して列を解放したい（新しい列が使えるようになる）
- **US-05**: プレイヤーとして、通常カードをどのカテゴリに属するか判断して列に配置したい（言葉の分類力を試せる）
- **US-06**: プレイヤーとして、残り手数を常に把握したい（残り手数内に全カードを置けるか判断できる）
- **US-07**: プレイヤーとして、全カードを正しく配置できたらクリア達成の演出を見たい（達成感を得られる）
- **US-08**: プレイヤーとして、手数が尽きてクリアできなかった場合はリトライしたい（再挑戦できる）

#### 補助機能
- **US-09**: プレイヤーとして、行き詰まったときにヒントをもらいたい（どのカードをどこに置けばよいか）
- **US-10**: プレイヤーとして、直前の操作を取り消したい（アンドゥ機能）
- **US-11**: プレイヤーとして、特殊なブースター機能を使って局面を打開したい

### 1.3 プレイヤーが体験する価値
1. **知的達成感**: カードの単語を見てカテゴリを推測・判断する認知的楽しさ
2. **適度な緊張感**: 手数制限による「あと少し」のテンション
3. **発見の喜び**: めくったカードがカテゴリカードだったときのサプライズ
4. **短時間完結**: 1ステージ3〜8分でプレイ完結するカジュアル設計

## 2. システム要件

### 2.1 機能要件

#### FR-01: ステージ管理
- ステージ一覧をTurso DBから取得して表示する
- ステージごとにカード一覧・カテゴリ一覧・制限手数が定義される
- MVPでは1ステージ（ステージ1）のみ実装

#### FR-02: ゲーム初期化
- ステージデータ（カード・カテゴリ）をDBから取得する
- カードをシャッフルして4列のスタックに均等配布する
- 初期状態で1列のみカテゴリカードが配置され（残り3列はロック）
- カテゴリカードはシャッフル後のデッキや場に混入する

#### FR-03: 山札操作
- 右上山札（メイン山札）から1枚カードをめくれる
- めくったカードは中央の捨て山（面表）に積まれる
- めくるたびに手数が1減る

#### FR-04: 場のカード操作
- 各スタックの一番下（最後）のカードのみ取得可能
- カードを取得すると手数が1減る

#### FR-05: カテゴリカードの配置
- カテゴリカード（type='category'）を取得後、ロック解除済みの空きスロットに配置できる
- 配置するとそのスロットが「filled」状態になり、対応カテゴリが解放される

#### FR-06: 通常カードの配置
- 通常カード（type='normal'）を取得後、解放済みカテゴリ列に配置できる
- どのカテゴリ列に置くかはプレイヤーが判断する（バリデーションなし or 正誤判定あり）
- MVP: 配置後に正誤が視覚的にフィードバックされる（正解: 緑、不正解: 赤）

#### FR-07: ゲーム終了判定
- 全カードが配置済みかつ正しいカテゴリに収まっている → クリア
- 手数が0になり未配置カードが残る → 失敗

#### FR-08: ブースター機能（MVP最低限）
- **ヒント**: 配置可能なカードとカテゴリのヒントを表示
- **アンドゥ**: 直前の操作を1手戻す
- **特殊ブースター**: （MVP後に詳細化）

#### FR-09: 進捗保存
- クリア時にプレイヤー進捗（クリア済み・残り手数）をTurso DBに保存する
- プレイヤーIDはブラウザLocalStorage/UUIDv4で管理（ログイン不要）

### 2.2 非機能要件

#### NFR-01: パフォーマンス
- ゲーム画面の初期表示: 3秒以内（DBからのデータ取得含む）
- カード操作のアニメーション: 60fps維持
- Framer Motionによるカードアニメーションが滑らかに動作すること

#### NFR-02: レスポンシブ対応
- モバイル縦持ち（375px〜430px幅）を主対象として設計
- タブレット・デスクトップでも表示崩れなく動作すること
- タッチ操作の最小タップ領域: 44×44px以上

#### NFR-03: アクセシビリティ
- カード上のテキストが読みやすいフォントサイズ（最小14px）
- ゲーム状態（手数、クリア/失敗）がスクリーンリーダーに伝わること

#### NFR-04: 信頼性
- Turso DB接続失敗時は適切なエラーメッセージを表示
- ゲーム中のブラウザリロード後、ステージ選択画面に戻れること

#### NFR-05: Capacitor対応
- 将来的にCapacitor 8でのネイティブアプリ化を想定したアーキテクチャ
- `BUILD_TARGET` 環境変数で `web` / `mobile` を切り替え可能な設計
- ゲームロジックはクライアントサイドのみで完結させること

#### NFR-06: セキュリティ
- Turso接続情報（TURSO_DATABASE_URL, TURSO_AUTH_TOKEN）は環境変数で管理
- .env ファイルはgit管理対象外

## 3. MVPスコープ

### 3.1 MVP（今回実装）

| 機能 | 詳細 |
|------|------|
| ステージ1の実装 | カテゴリ4〜5種・カード合計32〜40枚 |
| ゲーム基本ループ | 山札めくり→カード取得→カテゴリ配置→クリア/失敗 |
| 4列レイアウト | カテゴリスロット4列・スタック4列・山札 |
| カテゴリ解放 | 1列スタート、カテゴリカードで列解放 |
| 手数制限 | 設定された手数でゲームオーバー |
| ヒント機能 | 1ステージ3回使用可能な基本ヒント |
| アンドゥ機能 | 1手戻る |
| クリア/失敗画面 | 結果表示・リトライボタン |
| TursoDB連携 | カード・カテゴリ・ステージデータの取得 |
| 進捗保存 | クリア記録・残り手数保存 |

### 3.2 将来フェーズ（MVP対象外）

|------|------|

## 4. 受け入れ条件

### AC-01: ゲーム基本ループ
- [ ] ステージ選択画面からステージ1を選択するとゲームが開始される
- [ ] 山札から1枚カードをめくれ、手数が1減る
- [ ] 場のスタックの一番下のカードを取得でき、手数が1減る
- [ ] カテゴリカードをスロットに配置すると、そのスロットが解放される
- [ ] 通常カードを解放済みカテゴリ列に配置できる
- [ ] 全カード配置完了でクリア画面が表示される
- [ ] 手数0で未配置カードがある場合は失敗画面が表示される

### AC-02: 手数管理
- [ ] ヘッダーに現在の残り手数が常に表示される
- [ ] カードを取得・配置するたびに手数が正しく減算される
- [ ] 手数が0になった瞬間に失敗判定が行われる

### AC-03: カテゴリ列管理
- [ ] 初期状態で4列中1列のみカテゴリが表示され、残り3列はロック表示
- [ ] カテゴリカードをロック解除された空きスロットに配置すると列が解放される
- [ ] 解放された列にカードを配置できる

### AC-04: DB連携
- [ ] ステージ1のカード・カテゴリデータがTurso DBから正しく取得される
- [ ] クリア時に進捗データがTurso DBに保存される

### AC-05: UI/UX
- [ ] モバイル縦持ち（375px幅）で全UI要素が正常に表示される
- [ ] カードのドラッグまたはタップ操作が正常に動作する
- [ ] アンドゥボタンで直前の操作が取り消せる
- [ ] ヒントボタンでプレイヤーに有効な手のヒントが表示される

### AC-06: パフォーマンス
- [ ] ゲーム画面初期表示が3秒以内（低速回線3G想定でも）
- [ ] カードアニメーションが目視で滑らかに動作する（カク付きなし）
